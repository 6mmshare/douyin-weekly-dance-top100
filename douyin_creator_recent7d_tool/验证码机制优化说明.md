# 新工具验证码机制优化说明

## 修改范围

本次只修改：

```text
douyin_creator_recent7d_tool\01_collect_recent_videos.py
douyin_creator_recent7d_tool\creator_recent7d_config.yaml
```

原Top100项目的Python、BAT、配置、任务计划、断点和输出均未修改。

## 复用方式

这里的“复用上一级校验机制”是把上一级已经实际使用过的验证码判断规则复制到新工具中，而不是让新工具导入或修改原Top100代码。

这样可以同时满足：

- 两边使用相同思路；
- 原Top100保持完全不动；
- 新工具以后可独立升级。

## 新验证码判断规则

程序不再因为以下情况暂停：

- 搜索页面正在显示骨架屏；
- HTML中存在`captcha`或`verify`文字；
- 页面预加载了隐藏验证码iframe；
- 隐藏的验证码DOM仍留在页面；
- 普通搜索结果已经正常显示；
- 单独出现“验证码”或“安全验证”弱文案。

只有出现真实可见的强信号组合才暂停，例如：

1. 浏览器已经进入明确验证码URL；
2. 可见的“请完成验证/拖动滑块/完成拼图”弹窗；
3. 可见验证码iframe并同时出现滑块、遮罩或强提示；
4. 可见的大面积验证遮罩和挑战控件；
5. 强信号连续检测至少2次。

## 用户验证期间

真正出现验证码后：

1. 程序暂停当前博主；
2. 不会继续搜索下一个账号；
3. 不需要在黑框按回车；
4. 在浏览器中完成验证；
5. 验证消失后连续稳定5秒；
6. 再额外等待4秒让页面恢复；
7. 继续当前博主，而不是跳到下一个博主。

## 后台模式

后台版检测到真实验证码时：

- 保存断点；
- 停止运行；
- 不会继续乱跑。

然后运行：

```text
01_抓取最近7天视频_前台.bat
```

完成验证后从断点继续。

## 可调整配置

文件：

```text
creator_recent7d_config.yaml
```

相关配置：

```yaml
verification_wait_timeout_seconds: 900
verification_poll_seconds: 1.5
verification_stable_clear_seconds: 5
verification_required_consecutive_hits: 2
verification_confirm_interval_seconds: 0.9
verification_post_clear_wait_seconds: 4
```

通常不用修改。
